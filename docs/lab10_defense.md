# Практическая работа № 10 на 8 баллов

Реализованы интеграционные тесты на Testcontainers, нагрузочный сценарий
Locust и GitHub Actions. Дополнительные задания Pact и mutmut не добавлялись.

## Подготовка на другом компьютере

Установите Python 3.11, Git, Docker Desktop (Linux containers) или Docker
Engine с Compose. Запустите Docker. Интернет нужен для зависимостей и образов.
Из корня проекта в PowerShell:

```powershell
py -3.11 -m venv .venv
$py = ".\.venv\Scripts\python.exe"
& $py -m pip install -r requirements-dev.txt
& $py -m pytest tests/integration -v
```

В Linux/macOS: `python3.11 -m venv .venv`, `source .venv/bin/activate`,
`python -m pip install -r requirements-dev.txt`, затем те же команды
с `python` вместо `& $py`.

Для новой интеграционной части **не нужны .env, Compose и запущенный API**:
фикстура сама поднимает временные PostgreSQL 15 и Redis 7, запускает миграции
Alembic и отдельный FastAPI на случайном порту. После запуска всё удаляется.
Docker должен быть доступен текущему пользователю.

## 1. Что сказать и показать в тестах

«Интеграционные тесты проверяют HTTP → аутентификацию → сервис → репозиторий
→ настоящую PostgreSQL. Каждая сессия получает временные контейнеры,
а каждый тест начинает с очищенных таблиц и Redis. Рабочая база не используется».

```powershell
& $py -m pytest tests/integration -v
```

Покажите зелёный результат, затем:

- `scripts/lab10_environment.py` — создание контейнеров, миграции и отдельный API.
- `tests/integration/conftest.py` — фикстуры, очистка данных между тестами,
  регистрация и JWT через реальные эндпоинты.
- `tests/integration/test_orders.py` — сохранение заказа, количества, суммы и
  баланса; отрицательные сценарии; повтор оплаты без второго события;
  IDOR; чтение меню и 404.

Примеры методички адаптированы к API проекта: пользователь берётся из JWT,
создание возвращает 200, списанная сумма хранится как charged_amount.
Недостаточно сделать rollback в тесте: API выполняет commit в другом процессе,
поэтому между тестами очищаются таблицы именно в одноразовом контейнере.

Отдельно unit-тесты без Docker:

```powershell
& $py -m pytest -q tests/test_architecture.py tests/test_auth_service.py tests/test_grpc_client.py tests/test_orders_service.py tests/test_rate_limit.py tests/test_tasks.py tests/test_users_service.py
```

Старые интеграционные тесты tests/test_security_api.py и tests/test_menu_cache.py
оставлены для предыдущих работ. Они требуют инфраструктуры Compose и
запускаются отдельно от нового стенда. Команда CI запускает выбранные unit-тесты и набор tests/practice,
затем запускает новую интеграционную часть.

## 2. Нагрузка и узкое место

Запуск с интерфейсом:

```powershell
& $py -m scripts.run_lab10_load --web
```

Дождитесь строки Locust: http://127.0.0.1:8089. Откройте адрес и задайте
50 пользователей, spawn rate 10, затем увеличьте до 200.
Смотрите Statistics и Charts: RPS, p95 и failures. Выход Ctrl+C завершает стенд.
Порты API, PostgreSQL и Redis выделяются автоматически.

Автоматический прогон двух уровней нагрузки и сохранение отчётов:

```powershell
& $py -m scripts.run_lab10_load
```

По умолчанию два прогона по 40 секунд, 50 и 200 пользователей, по 10 новых
пользователей в секунду, с паузой 1–3 секунды. Время разгона входит в 40 секунд.
Для более длительного наблюдения: `--seconds 90`.

Сценарий `loadtests/locustfile.py`: веса 7/2/1 для списка, карточки и
создания заказа. У каждого виртуального пользователя свой заранее созданный
аккаунт и настоящий JWT, достаточный баланс. Нагрузочные запросы проходят
обычную проверку JWT; массовый логин и его rate limit не подменяют нагрузку
на бизнес-эндпоинты. Эти токены действуют 15 минут; для новой длительной сессии
перезапустите стенд. Доступно до 1000 аккаунтов по умолчанию.

Стенд не запускает оплату, кухню и доставку: в этой работе нагрузка проверяет
создание заказа и чтение меню. Уведомления Celery ставятся в изолированный
Redis без worker и уничтожаются вместе со стендом.

Отчёты: `docs/lab10/load/*_stats.csv`, `*_failures.csv`,
`*_resources.json`, `summary.json`. HTML-отчёты создаются локально рядом.
JSON ресурсов содержит CPU процесса API (100% = одно ядро), память и
число активных запросов PostgreSQL/ожиданий блокировки. Сравнение и выводы —
в `load_results.md`. Сохранённые числа относятся к конкретному компьютеру,
а не являются обещанием производительности на другой машине.

Для поиска насыщения есть отдельный режим:
`python -m scripts.run_lab10_load --stress --users 200 --output docs/lab10/load/stress`.
Он сокращает паузы до 0,01–0,05 секунды. Сравнение двух процессов API:
та же команда с `--workers 2 --output docs/lab10/load/two_workers`.
Обычный и стресс-сценарий не следует смешивать в одном сравнении.

## 3. CI и запрет слияния


Workflow `.github/workflows/test.yml` запускается на каждый push и pull_request.
Он устанавливает зависимости, запускает unit-тесты, tests/practice и интеграционные
тесты с Testcontainers. XML-результаты прикладываются к запуску Actions.

Один workflow сам по себе не запрещает merge: в правиле ветки main должна
быть обязательная проверка `tests`. Проверка не пропускается по фильтру путей.
На защите покажите зелёный запуск main и отдельный демонстрационный PR
с намеренно падающим тестом: тест красный, обязательная проверка блокирует
слияние. Этот тест находится в отдельной ветке, основная рабочая версия зелёная.

## Ответы на вопросы

- Unit проверяет отдельную логику без внешних служб; интеграционный проверяет
  несколько настоящих компонентов; E2E охватывает пользовательский путь.
- Testcontainers создаёт воспроизводимую чистую среду и убирает зависимости
  от локальной базы и старых данных.
- Пирамида: много быстрых unit, меньше интеграционных, мало дорогих E2E.
- p95 — 95% запросов завершились не дольше этого времени.
- Рост задержки без роста пропускной способности — признак насыщения;
  для причины нужны измерения ресурсов, БД и конкретных эндпоинтов.
- 90% покрытия не гарантируют обнаружение ошибки: строка могла выполниться,
  но тест не проверил результат. Здесь проверяются сумма, баланс и запись в БД.
- Pact проверяет совместимость контрактов, mutmut — чувствительность тестов
  к изменениям логики; эти бонусы не входят в выбранный уровень.
