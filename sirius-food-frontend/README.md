# Сириус.Еда — SSR витрина для ЛР № 8

Next.js App Router получает данные с FastAPI по REST. `/` перенаправляет на `/menu`. Серверный компонент списка находится в `src/app/menu/(list)/page.tsx`; карточка — в `src/app/menu/[id]/page.tsx`. Группа `(list)` не меняет URL и ограничивает скелетон списком: карточка при отсутствии блюда сохраняет HTTP 404. Ошибку запроса перехватывает общий `src/app/menu/error.tsx`.

Подготовьте API и заполните меню по [инструкции из корня](../docs/start_labs_6-9.md#4-лр--8-витрина). В этой папке скопируйте `.env.example` в `.env.local`, выполните `npm ci` и `npm run dev`, откройте [localhost:3000](http://localhost:3000). В Windows PowerShell можно использовать `npm.cmd`. Сборка: `npm run build`; запуск сборки: `npm start`.

Проверка SSR: `bash check.sh` при работающем API и фронтенде (нужны curl и Python 3). В Git Bash можно явно указать Python: `PYTHON_BIN=../.venv/Scripts/python.exe bash check.sh`. На тестовом стенде проверка дала `PASS=6 FAIL=0`: API отдаёт список и карточку, неизвестный ID даёт 404 и в API, и на фронтенде, а оба SSR-маршрута содержат название блюда в HTML.

В браузере откройте исходник страницы Ctrl+U и найдите «Сырники»; в исходнике карточки должны быть название и цена. Остановите API, откройте существующую карточку, затем поднимите API и нажмите «Попробовать снова». Подробный [сценарий защиты](../docs/lab8_defense.md).
